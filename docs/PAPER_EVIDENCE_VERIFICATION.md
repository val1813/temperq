# 既有纸面账本的只读核验

`paper verify`核对已有`paper_daily_v1/v2`账户的冻结身份、完整日历、记录时点与状态内部一致性。它不新建账户、不下载数据、不推理、不追加记录、不启用自动化，也不修复或迁移账户。仅适用于`runs/paper/<name>`；不把另一个`runs/strategies`版本账本、券商账户或策略导入审计当成相同格式。v2的声明事件存档、阶段和状态语义核验见[公司行动验收](PAPER_CORPORATE_ACTIONS.md)，不认证独立权益或到账。

```powershell
python -m qwb.cli paper verify <已有账户名> --calendar <完整日历.csv> --through 2026-11-05 --source-kind local_paper --out <账户目录外的新报告.json> --json
```

省略`--through`时检查至本机上海时区最近已完成收盘的自然日（15:30前截止前一自然日）；周末和节假日由提交的日历决定。未来未收盘日期拒绝。`--minimum-forward-intervals`默认为60，指首条基线之后、两端均合格的相邻前向收益区间，61条连续合格快照才可能产生60个区间。这个建议值是项目验收目标，不是监管标准；少于门槛仍保留报告，但不给通过。

退出码0要求本地一致性`status=matched`且本地前向覆盖`local_forward_coverage_gate=passed`；历史完整账本通常返回1，因为前向区间为零。输入、版本、坏材料及已有输出等错误也沿用paper CLI退出码1，标准错误说明原因；不会覆盖已有报告。`--out`不得位于任何`runs/paper`账户之内。

## 核验范围

- 以SQLite `mode=ro`与`query_only`读取已有账本，事务内取得一个元数据/会话快照；缺库不创建库。配置摘要、当前执行实现摘要、冻结模型文件摘要与协议摘要必须匹配。
- 日历为唯一的`date,is_open`两列，开市1、休市0，覆盖启用日至核验日每个自然日。缺日、重复或不规范日期拒绝；不能用双方共同缺记录或仅有工作日的日历证明连续。
- SQL日期与JSON日期一致，所有预期开市日均有快照；检查记录来源标签、model/protocol/snapshot身份，AccountState合法性、权益与持仓现金的内部一致性、相邻权益对应的日收益，初始现金/库存与配置一致。
- 有目标权重时，下次执行日须为日历下一开市日；空字典代表全现金目标，仍须有执行日。下一执行日超出日历覆盖时材料不足，不能默认为及时记录。
- `forward_paper`标签还须有当日15:30后、当日午夜前保存的记录，且不早于账户启用、不晚于核验时间。有前一期决策待执行时，前一期真实`recorded_at`须早于本日09:30，不能只信任布尔字段。首个快照只是基线，没有前一日收益。
- 历史演示与迟到重建分别计数，不累计成合格前向收益；跨缺日或跨迟到记录不拼接前向收益区间。显式`--source-kind synthetic_fixture`永远贡献零个前向区间，即使内容里写着forward。

报告只提供日期、计数、问题代码、摘要和边界，不回显具体持仓、现金、模型系数、数据路径或未知来源标签的原始文本；问题最多列1000项并保留真实总数。报告绑定计算源码和读取的逻辑账本快照，不能借当前数据库文件哈希证明并发写入期间的整个文件始终不变。SQLite在WAL模式下仍可能管理读锁/共享内存，核验器本身不执行账本写语句；独立快照文件更适合归档复算。

## 本轮修复

2026-11-06补充：记录器的计算截止时间与保存时钟已分离。`strategy_workspace.tick`原先直接将调用者的`now`写入`recorded_at`，而`paper.tick`虽然保存系统时间，却用调用者的`now`判断前向标签和决策是否早于执行。两处均可让历史补录获得错误的及时标记。修复前两个复现测试实际失败，旧结果保留，不能把旧版本的及时标签作为可靠前向证据。

现在两个记录器均在写入记录前读取本机系统时间；上海时区当日15:30后、启用后保存，且上一项待执行决策确实在本日开盘前保存，才给`forward_paper`标签。判断同时核对上一记录的时间戳，不能只凭布尔标记。`strategy_workspace.start`的`activated_at`也使用系统时间。调用者的`now`只限制计算截止，未来截止会被限制到本机当前时刻；较早截止仍可用于历史回放。跨午夜完成计算记为迟到，不使用计算开始时刻冒充保存时刻。

这些时间来自本机时钟、在数据库插入前采样，不是独立时间戳服务或事务持久化时间证明。管理员改时钟、文件和数据库仍可破坏证据；当前没有声称实现不可篡改日志。旧账户和旧验证计划未改写，执行源码摘要变化会要求新版本。后续公司行动接入仅对新事件数据源与新账户生效；旧v1复权变化时的安全暂停继续保留。

新增`tests/test_paper_recording_clock.py`覆盖两种账本的实际保存时钟、UTC与上海日期、迟到、下一开盘边界、未来截止、计算跨午夜以及前一期错误及时标记。原正常前向测试改为显式模拟系统时钟，不能再只传`now`就制造前向记录。

同轮扩展至外部信号接收：`external_signals.append`原先将`now`存为首次接收日期，也允许未来截止提前接收未来预测。新增三个复现均在修复前失败；现在按本机时钟记录首次接收，追加不改写旧日期，接收和使用预测的截止均不超过当前系统时刻。旧版接收日期未追溯认证，不能仅凭旧快照摘要证明当时已收到。调用者声明的`generated_at`仍是声明，未认证上游训练或无前视性。

旧`paper.tick`在尚无账户状态时没有检查首个开市日。已知日历包含启用日、该日行情缺失、后一天行情存在时，它会直接从后一天起算并标RUNNING。现在停在WAITING_DATA，补齐派生行情后保留原启用日起算，不跳日。既有中间日缺行情暂停逻辑继续使用；不能据此认证本身缺失/错误的日历。

另修复空目标`{}`的记录：原来已表达清仓到现金，但`next_execution_day`因空字典为假而记成null。现在以“是否为None”判断，空目标与未做决策分开记录。此项有单位测试；正常生成器目前不生成空目标，不能冒称正常回放已触发了该边界。

`paper.py`发生变化，旧账户原先冻结的执行实现摘要会失配并安全停止。**未迁移、重签、改写或重启任何用户旧账户。** 旧文件保留；按原规则由用户建立新版本，不能强行修改摘要继续旧成绩。冻结验证计划绑定所有qwb Python源码，因此旧计划也需在新版本另行冻结，历史计划与结果保留。

## 验证与边界

```powershell
python -m pytest -q tests/test_paper_verification.py tests/test_daily_strategy.py tests/test_daily_operation.py tests/test_workflow_ui.py
python scripts/verify_paper_evidence.py --out <全新隔离目录>
```

实际验证器从合成Parquet、完整自然日日历和零系数Ridge模型走现有加载、打分、原生纸面执行及SQLite记账链路，七个历史会话、重启幂等、缺首日暂停及补齐恢复均实际执行；没有替换数据加载器或执行器。读取正常/恢复账户、缺中间日、错权益、历史冒充前向、冻结模型变化和坏日历七类CLI检查，逐次核对账户文件未改。代码里“实际执行器”指本项目已有纸面执行器，不指此前外部专业引擎，也不是券商。

第一轮复现测试在修复前实际失败；另一次定向回归有三项失败，原因是测试将历史fixture改标为forward但漏改旧的及时决策布尔值。应用正确拒绝不一致，之后只修fixture，没有放宽核验器。失败材料及更正后记录分别保留。

本地日历、模型、时间、标签和账户关系均未独立认证；持有全部文件与摘要的管理员可同时伪造它们。测试中主动重签合成配置能得到本地覆盖通过，但报告仍明确时间/来源未认证，不能将它写成真实前向观察。`status=matched`也不复算完整撮合过程、不验证母单生命周期、公司行动权益/税率/结算资金，不替代独立券商对账、60个真实时间区间或机构准入。既有公司行动安全暂停不因核验器而放开。
