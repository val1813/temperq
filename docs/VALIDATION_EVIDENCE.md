# 策略版本下的账户、归因与风险证据

策略导入页的“账户、归因与风险证据”连接日终账户核对、行业／风格归因及风险估计与留出诊断。它补充原有“独立成交与执行材料”，把独立提交的原始文件、来源声明、计算代码摘要及逐项结果绑定到当前策略材料版本。关联只作上下文，不能证明账户属于策略，也不更改原策略、原审计报告或账户规则。

## 日终账户核对

上传两份独立账户ZIP与一份完整日期日历CSV。每份ZIP只能在根目录包含以下五个文件：

- scope.json
- balances.csv
- positions.csv
- fills.csv
- events.csv

字段及期初、事件、成交日总现金约定见 [日终账户核对](ACCOUNT_RECONCILIATION.md)。页面分别显示匹配、差异或证据不足；逐项列出双方差异及各自推演异常，订单明细与完整检查保留在JSON。双方同时少一天不能匹配，入金、送转及费用记录不能用未知调整冲平。

ZIP在内存逐成员读取，**不解压到磁盘、不执行代码**。重复成员、额外文件、嵌套路径、缺文件、加密、损坏压缩流或不支持的压缩方式拒绝。单上传文件最多8MB，合计24MB；每份账户ZIP展开最多32MB、单成员最多8MB。模板下载中的外层ZIP含内部ZIP、外部ZIP、日历及说明；上传时分别选择里面的两个账户ZIP和日历，不上传模板外层ZIP。

## 行业／风格归因

分别上传范围与模型JSON、区间收益、完整期初权重、带可得时间暴露、同区间因子收益五个文件。字段、双时间版本选择、过期与多期链接公式见 [时点因子归因](FACTOR_ATTRIBUTION.md)。

页面区分完整分解与证据不足：缺材料时不给完整多期归因；已知部分暴露仅用于定位缺口。完整材料分别显示组合、基准、主动的链接贡献及残差，残差明确不是alpha。区间覆盖、缺口和贡献均可横向滚动查看；完整明细在JSON，不以页面最多100行限制统计分母。

行业／风格归因不是风险协方差、特异风险、VaR或风险预算；软件不会据此出“机构准入通过”。来源可选历史材料、合成材料或历史收益混合合成暴露；混合材料不会被升级为真实模型验证。

## 风险估计与留出诊断

分别上传风险范围与模型、完整自然日日历、相邻收盘区间、截止时点完整权重、历史可得暴露、因子收益与证券总收益七份材料。字段、计算方法、收缩、训练/留出时点及统计限制见[风险模型诊断](RISK_MODEL_VALIDATION.md)。网页单文件8MB、合计24MB，低于CLI合计48MiB限制；沿用原有请求总量边界。

页面显示组合、基准、主动的波动、模型高斯VaR/ES、因子/残差/交叉方差、逐证券波动贡献及留出实际波动、超限次数与检验。模型定义、贡献及尾部检验可展开，完整材料和逐期序列保存在JSON。协方差秩不足、零方差、缺状态变化、尾部预期次数不足及未认证来源均明确提示；大p值不变成“通过”。所有结果固定标明模型未校准、机构准入未建立。

训练缺数据时不给预测；留出材料不足时保留已经完整计算的预测，但不对部分样本给出完整诊断。未来权重、日历缺口及格式错误在保存前拒绝。页面区分这些状态，不把它们都写成模型好坏结论。

这是固定目标权重每期无成本再平衡、现金收益为零的回顾性模型组合，不是真实交易净值，也不构成前向冻结、独立盲测、真实模型校准或ES独立回测。模型参数/完整性在空模板中仍待填写；模板不预填完整性true，不提供伪装真实的样本收益。

## 保存与版本核对

每次提交主动选择来源，并声明范围、完整性、时间和单位口径。空模板不预填完整性为true；没有示例成交可被误认为真实记录。备注可选，最多80字，不填密钥。

保存路径为工作目录下 `runs/strategy_audits/<材料版本ID>/validation_evidence/<证据ID>/`。每次使用新编号，不覆盖旧目录；保存原始上传ZIP/CSV/JSON后，最后写完整报告，未完成目录仍在历史中提示。报告包括策略材料digest、输入SHA-256/字节数、计算代码SHA-256、来源声明、结果digest和明确的 institutional_readiness=not_established。

每次打开、下载JSON或输入文件，核对策略版本、清单、代码及输入摘要，再从原始输入重新计算；结果不一致即停止展示为有效证据。跨策略引用、过期输入digest、改CSV、篡改结果后重算其摘要均不能通过。计算模块或依赖代码变化会要求重新验证，保留原记录；风险模式也绑定NumPy/SciPy/Python及架构版本。网页不把旧结果无提示地升级到新算法。恢复旧版本复核应使用其冻结代码，当前代码重新上传则生成新证据编号。

本轮保存模块加入风险模式，其文件摘要发生变化，因此以前账户/因子证据在当前代码下也会提示重新验证；原目录、原输入与冻结交付清单保持原样，没有重写历史报告或自动改来源。

本入口没有机构签署或审批，也没有远端服务、账户启用或计划任务。文件一致及哈希核对不能认证外部来源、完整性、机构资质，或防御能一致重写代码和全部原材料的系统管理员。

## 实测

`scripts/qa_validation_evidence.mjs` 验证纯合成材料导入、账户正常/差异、完整因子/缺暴露、原始输入与JSON下载、版本关联和1440/390/320像素。模板/下载响应no-store及nosniff，网页明细窄屏横向滚动。首轮浏览器因QA服务启动时漏传端口被Host校验正确阻止；修正隔离服务配置后完成，未绕过Host或CSRF检查。早期窄屏竖排截图与失败产物保留。

`scripts/qa_native_validation_evidence.mjs` 使用已有原生模拟probe及按原资料打包的规范账本，走真实浏览器入口。已验证历史价格模拟36日/38笔，双方资金/持仓核对通过，JSON保留simulator_native和real_broker_validation=false。这是同一模拟引擎的两条报告路径，共用估值；原installed执行模式的时点限制仍保留。网页关联不把它转为独立券商账务或真实执行验证。

`scripts/qa_risk_evidence.mjs`要求显式合成fixture，走真实浏览器上传、保存、七份原文件/JSON下载与策略版本关联。覆盖完整预测、未来输入不改预测、留出冲击、缺训练/留出材料、零主动风险、未来权重及日历缺口拒绝、跨策略拒绝和1440/390/320像素。旧账户/因子QA也已更新三种模板入口及列表标题。本轮视觉复查修正窄屏来源、备注与声明挤在同一行的问题；修改后受影响的风险、账户/因子及原生账户三条脚本再次通过。初次脚本错误地把页面标题当作可见h1的失败截图保留，实际错误页面原本已有role=alert，未放松校验。

所有QA使用独立工作目录，不操作用户账户或策略；结束后精确停止本轮隔离服务。完整回归、旧流程复查和证据位置见 [工程验收记录](INSTITUTIONAL_ACCEPTANCE_20261105.md)。
