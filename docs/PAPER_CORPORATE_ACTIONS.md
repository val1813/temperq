# 公司行动与纸面账户验收

2026-11-06。新增的是声明事件驱动的原始股数核算，不是机构认证，也不是实盘或税务结算证明。旧账户、旧模型和旧证据未迁移；执行摘要变化后须建立新账户版本。

## 已接通的路径

`paper_corporate_actions.py`负责事件输入、覆盖、版本、存档和时点摘要；`portfolio/lifecycle.py`负责权益变动。日线导入、历史政策比较、两种纸面账户、STRUCT成本路径、暂停恢复及部署看板复用同一内核。原`corporate_actions.py`继续只对导入平台记录提出有标签的推断，不作为纸面事件来源。

支持普通现金分红、整数拆并股与显式送转股。现金分红分别登记、确认应收和支付，应收不能直接融资；支付将应收转为现金，不重复产生收益。送转在登记日保留权益，除权日新增股数计入持仓估值，可卖日前以独立未结算批次锁定。到账、除权、上市可卖时间不得互相替代。

日频适配只接受开市日09:00阶段和15:00登记。送转登记日必须是除权前一开市日；不自动移动日期。零碎股、配股、复杂合并、重叠股份变换、终止事项、按持有期递补扣税以及未知期初权益均不自动处理，明确拒绝或暂停。普通拆股保持原结算批次；存在延迟可卖日的送转必须使用`bonus_shares`，不能用`split`伪装为立即可卖。

## 导入与版本

```powershell
python -m qwb.cli paper update-data <全新数据源> <日线.csv> --calendar <完整日历.csv> --corporate-actions <事件.json>
```

网页`/paper/data`也可上传事件JSON。已有无事件数据源不能原地升级，需另建数据源及账户版本。普通追加继承事件文档；扩展覆盖或新增事件必须增加版本、引用前版摘要。既有事件、因子关联与历史日历不能静默改写，既有覆盖不能缩减。新事件若改变已记录决策当时应知的信息，停止追加并要求新版本。

全市场API更新也继承并核验事件文档，不会由复权因子推造事件。可使用`python scripts/fetch_full_market.py --feed <数据源> --end <已完成日期> --corporate-actions <后续版本.json>`提交显式扩展；即使没有新增行情，也会为变化的事件版本生成不可变快照。同版本同日重试保持幂等。事件文件缺失、摘要不符、既有事件修订或历史日历修订均停止发布；已有无事件API源仍需另建。继承不会自动延长覆盖期，覆盖不足的账户继续暂停。

事件格式为`paper_corporate_actions_v1`，顶层字段严格限定为`schema_version,version,previous_digest,source,coverage,actions,factor_changes`。`source`含`kind,reference`，类别为`provider_archive/user_declared/synthetic_fixture`。合成来源不能开启真实前向账户。每只持仓和候选证券须声明覆盖开始/截止；复权变化须关联具体事件ID和前后因子，不能仅从因子反推现金或股数。相同证券、种类和生效时间重复公告须先核实为唯一经济事件，不能重复记权益。

具体事件字段和可运行材料由`scripts/verify_corporate_actions_e2e.py`生成。输入文档绑定行情快照身份，每条账本记录绑定完整文档摘要和决策时已知事件摘要。原文保存在账户版本的`ca_inputs`，短文件名用于Windows路径兼容，每次读仍核验完整SHA-256；存档缺失或被改不能继续追加。历史评估引用策略版本的存档，避免深层目录超限。

`paper verify`兼容`paper_daily_v1/v2`。v2额外检查存档摘要、声明来源、事件版本链、开市日阶段、决策时已知事件摘要、处理阶段集合和应收语义。报告中的本地状态语义通过不是独立权益认证；`corporate_action_entitlements_verified`仍为false。该入口不完整重演撮合，不能证明管理员未同时改写所有材料。

## 已执行验收

端到端脚本在全新隔离目录使用实际CSV导入CLI、Parquet加载、完整自然日日历、SQLite及本项目执行器。模型是零系数测试模型，历史分数为固定夹具，不构成策略收益证据。

- 合成现金分红加拆股、合成现金分红加延迟可卖送转，各覆盖旧纸面主线、新策略佣金路径及STRUCT路径。
- 历史检验与日更逐日状态及账户路径相等；缺事件暂停，补齐恢复；独立新进程同日重试不重复记账。
- 单元与联通测试覆盖旧账户不升级、已知事件修订拒绝、覆盖不足、因子关联不符、存档/阶段/应收篡改、周末支付拒绝、空持仓仍支付旧权益。
- 原有导入审计与新增适配器的模块重名已由全量回归发现并修复，原接口及原测试保留。失败记录不计通过。

```powershell
python scripts/verify_corporate_actions_e2e.py --out <全新验收目录> --api-sample <已归档接口样本目录>
```

省略`--api-sample`只运行合成用例。产物包含原始输入、来源限制、只读报告及源码摘要；目录已存在时拒绝覆盖。

## 真实历史样本的证据边界

已从用户配置的Tushare兼容第三方服务取得一只A股2025年1至9月183条日线、183条因子、183条涨跌停与273个自然日日历，以及111条全历史分红记录。分红表同一经济事项有两条公告记录，经济条款相同后合并为一项。2025-06-11登记、06-12除息及支付，每股声明现金0.362元；独立复制的隔离账户完成06-09至06-17连续回放。没有访问用户真实账户或2026封存行情。

该样本验证的是日期级历史核算：实施公告日期的23:59:59为声明的保守可用上界，不是历史接收时间；支付日09:00为日频核算代理，不是银行实际入账时间；税款使用供应方声明的毛额/净额，不认证投资者持有期税。样本覆盖不等于供应方全历史完整，单一事件也不能代表全市场公司行动。真实送转、复杂事项和独立到账验证仍待补。

机构使用仍缺真实券商成交/资金/持仓及事件的独立对账、冻结后的独立盲测、成本容量校准、真实前向时间与外部复核；这些不能被本次软件回放替代。
