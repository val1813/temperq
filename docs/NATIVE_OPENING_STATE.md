# 原生开盘执行时点修复与验收

本入口只用于已验证 LocalSMA 适配器的隔离回放。它不修改外部环境、原适配器、用户策略或已有结果，也不启用账户规则。NautilusTrader 固定为 1.231.0，外部 `quantlocal/engine.py` 必须匹配已核查 SHA-256 `e2d192c076e7419f45f6ae7ca7419465b18dd5cf1a30618240eb236ec36f4d90`；不匹配就拒绝生成副本。

## 修复内容

原适配器在 09:30 判断成交资格时读取当日最终成交量，用日线开盘价构造零价差、固定大数量报价。已证实只改变当日最终量就能改变开盘成交。

`scripts/native_opening_state.py` 根据固定源码生成新的执行副本，仅写入全新 probe 目录。信号、目标数量计算、下单时间、费用及原生账本保持原逻辑，执行材料改为独立的开盘报价：

- 09:30 资格判断只使用来源声明的报价及可交易状态，不读取当日最终量。
- 买入使用卖一价和卖一数量；卖出使用买一价和买一数量。
- 零对手方供给、不可交易、涨跌停限制仍阻断订单。不能删掉限制后假定无限供给。
- 原生引擎处理 IOC 部分成交和现金、持仓、费用。部分退出的残余库存保留，后续卖出信号重试；原策略对已有部分买入仓位不自动补足，该策略行为没有暗改。
- 收盘日线仅作估值；没有从日线伪造历史 L1 价差、供给或发布时间。

本轮模型改动属于明确声明的执行敏感性分支。不要以收益变高为准选择该分支；没有合格报价材料时不运行严格分支。

## 报价材料

UTF-8 CSV 字段：

```csv
date,symbol,observed_at,available_at,bid,ask,bid_size,ask_size,tradable,up_limit,down_limit,source_ref
2025-01-09,600000.SH,2025-01-09T09:29:59+08:00,2025-01-09T09:30:00+08:00,9.99,10.00,500,300,true,11.00,9.00,synthetic-example-only
```

这一行是合成格式示例，不能用作真实报价。每个请求的证券／交易日必须有且仅有一行；缺失不补零，不退回日最终量。字段要求：

| 字段 | 约定 |
| --- | --- |
| `date,symbol` | YYYY-MM-DD 及与配置一致的证券身份，重复、多余或缺失均拒绝 |
| `observed_at` | 行情／状态在市场发生的时间，含时区 |
| `available_at` | 该信息通过声明数据链路可被研究者取得的时间，含发布时间或接收延迟；不得用市场事件时间覆盖后来的发布时间 |
| 时序 | `observed_at ≤ available_at ≤ 当日09:30`，报价距09:30不超过60秒 |
| `bid,ask` | 元、正数、0.01元价位；买一不得高于卖一，报价不得越过声明的日涨跌停价 |
| `bid_size,ask_size` | 非负整数股；零是观测到的无供给，缺失是证据不足，不能混用；不是累计成交量 |
| `tradable` | 明确的 `true/false`，不能把空值当可交易 |
| `up_limit,down_limit` | 对应日期、下单前已知且有来源支持的价格限制；不从未来复权价格倒推 |
| `source_ref` | 指向实际行情来源或原记录的标识，不填账户密钥 |

单文件最多8MB。解析器验证声明字段和时间，**不认证来源、真实接收延迟或字段完整性**。报价快照也不等于当时可成交保证；历史成交量、集合竞价已成交量、日线成交量都不是 `bid_size/ask_size`。

## 运行

```powershell
python scripts/run_institutional_acceptance.py --engine-python <已有专业引擎解释器> --engine-root <引擎根目录> --config <配置.json> --calendar <交易日历缓存.json> --opening-state <开盘报价.csv> --opening-source-kind historical_quote --output <全新验收目录>
```

机构化运行器现在默认 `timestamped_opening`：缺报价或来源声明就失败，保留失败阶段与日志。若只是复现旧的账务验证，必须显式加 `--execution-profile installed`；输出仍披露最终日量的时点缺陷，不能充当严格执行验收。底层 probe 保留 installed 默认用于已有研究复现，机构化入口默认严格。

合成测试应加 `--market-source-kind synthetic_fixture --opening-source-kind synthetic_fixture`。真实日线混合合成报价时，报告会保留 `historical_real_prices_synthetic_opening_quotes...` 范围；完全合成材料不会标为真实行情。两条模拟报告路径仍是同一模拟来源，不构成独立券商对账。

运行器依次进行原生回放、交易日历、两条成交报告路径对账、TemperQ导入核账、完整审计与100股注错检查。生成的副本、开盘材料、原适配器及辅助代码均记录哈希，不覆盖旧产物。

2026-11-06 补充：提供日历时，在导入核账前还执行 [日终账户核对](ACCOUNT_RECONCILIATION.md)，核对回调成交推演的现金/库存与原生日终现金/库存，并验证现金、持仓及共同漏日三类注错；缺日历则该项标 not_checked。两条模拟报告路径仍不成为独立券商来源。

## 本轮实测与数据限制

固定专业引擎内的合成已知答案验证通过：买入300股、卖出300股、买入200股、卖出200股；四笔最低佣金20元，另卖出税费2.50元，价差损失5元，期末现金 **99972.50元**、持仓零。另验证部分退出100股后保留200股并在下一次卖出时退出；逐日现金、整数库存与权益独立复算闭合。

反事实检查包括：最终日量置零不改新分支订单与成交；旧适配器仍复现差异；修改当前及未来收盘价并重新计算SMA，截止当日开盘的信号、订单及成交不变；未来估值不改此前净值；分段与一次回放相同。缺报价与晚于开盘的发布时间均拒绝。

完全合成的8日资料也已从原生回放通过 TemperQ完整审计及注错流程。对已有真实行情配置省略报价时，严格入口实际失败，未把缺资料变成通过。

本轮实际核对的 [Tushare 开盘集合竞价官方文档](https://tushare.pro/document/2?doc_id=353)（2026-11-05读取）写明接口为 `stk_auction_o`，每天盘后更新、每个交易日20点更新。其归档值不能因此被声明为当日09:30经该API已取得的报价。该接口成交量也不等于盘口待成交量。已配置兼容网关对旧名 `stk_auction` 返回空字段空数据，通达信集合竞价请求返回502；两者均未用作报价证据，未开通付费权限。

**当前结论：隔离执行分支的因果与数量逻辑已通过合成原生引擎验证；真实开盘报价和可得性尚未验证。** 一档快照与IOC模型仍缺队列、延迟、补充供给、撤单和冲击校准。原外部适配器保留原样，旧回放不能因新分支通过而自动升级证据等级。
