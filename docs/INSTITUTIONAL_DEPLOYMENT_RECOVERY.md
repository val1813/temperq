第十四轮新增验收要求：重新构建当前源码的便携包，逐项比较非editable安装的全部qwb Python文件，并以随包解释器及`--installed`运行分红/拆股、分红/延迟可卖送转的六条隔离账户路径。子进程同样从安装包导入，不能靠源码路径绕过已安装模块；原网页审计和独立训练流程继续执行。对应结果以新目录内的`acceptance.json`为准，旧包通过不计作新源码通过。生产API的小范围只读取数另见[API数据完整性](API_DATA_INTEGRITY.md)。

新验收命令`python scripts/check_windows_portable.py <新包.zip> <新的深目录> --require-long-json-paths`要求两种合成公司行动情形均实际保存并读回超过260字符的JSON；结果记录数量和最长路径。验收仍需重建新包，不能仅修改已解压模块或复用短路径结果。短解压路径仍便于与其他Windows工具协作。

## 两个不同的环境

便携包使用独立CPython 3.11.15，安装`requirements.lock`和非editable项目/成本库，包含Microsoft C++/OpenMP运行库并校验原版数字签名；不包含Torch、可选求解器或私有数据。通过迁移目录中的BAT启动，不依赖原项目`.venv`或用户Python包。详细构建命令见[Windows便携版](WINDOWS_PORTABLE.md)。

可选求解器验收另建全新的虚拟环境，使用原有`requirements-e2e-windows.lock`，不改开发环境、不升级外部回放引擎。该锁采用Windows可用的CPU组合：Torch 2.11.0+cpu、CVXPY 1.5.3、CVXPYlayers 0.1.6、diffcp 1.0.23、NumPy 1.26.4、SciPy 1.13.1。它与基础环境及其他操作系统的可选锁不同，不能把一个组合的通过推广到另一个组合。

示意命令，输出与环境目录必须新建，源码应为已核对摘要的独立副本：

```powershell
uv venv --python 3.11.15 <新环境>
uv pip install --python <新环境>/Scripts/python.exe --only-binary :all: -r <源码副本>/requirements-e2e-windows.lock --torch-backend cpu
uv pip install --python <新环境>/Scripts/python.exe --no-deps <源码副本> <源码副本>/third_party/ashare-tcost
uv pip check --python <新环境>/Scripts/python.exe
```

完整pytest在独立源码副本运行，以覆盖测试所依赖的示例与文件；另从源码目录之外以`python -I -m qwb.cli e2e check --output <新目录>`运行已安装包，检查路径确实属于新环境。前者不是纯wheel测试，后者不证明完整网页或真实行情流程。

CI的`e2e-reference`原来仅选部分测试文件，基础环境又会跳过缺求解器的模块。本轮将该job改为完整pytest，并将JUnit放在参考检查输出目录之外，避免占用要求新建的CLI输出目录；两者都作为artifact保留。没有推送或触发远端workflow，本机Windows结果不能冒称GitHub或Linux验收通过。

## 便携包的实际流程

旧验收脚本仍要求首页显示“选择起步模板”，但当前首页已是策略治理工作区。第十一轮先构建旧脚本对应的当前包，实际迁移启动后在此断言失败，原始包、日志和失败结果均保留。修复检查脚本和随包说明，没有改首页来迁就旧测试。

更新后的`check_windows_portable.py`继续验证迁移目录启动、Microsoft DLL实际加载位置、字体和部署资源、四模板/规则卡入口及独立CPU训练worker。额外通过HTTP执行：下载应用合成示例、上传、核对材料、提交页面实际参数、进入策略治理、打开完整报告、下载证据，以及归因/比较/模拟准备页面可访问。合成例两日净盈亏183.90元、账务异常零、15个审计环节，均要求实际结果一致。

验收仅写新解压副本。PATH只保留系统目录，用户包禁用，故意提供无效Python环境路径；BAT解析随包解释器。Python审计钩子阻断父进程及worker的外网socket连接，允许本机HTTP。它不是操作系统级网络隔离，不证明能抵御主动绕过钩子的本地代码；没有用真实行情或券商材料冒充离线合成验收。
