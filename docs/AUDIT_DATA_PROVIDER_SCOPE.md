# 审计订阅版移除行情连接器的评估

2026-11-06。结论：审计产品可以不提供 Tushare，也不要求用户配置行情 token。保留现有审计检查的办法是接收原平台导出及明确格式的补充证据。当前仓库仍是同时包含训练、下载、纸面账户的完整工作台；本次没有把它改名为已裁剪完成的订阅包。

## 已核对的依赖边界

`audit_*.py` 没有直接调用 Tushare 客户端；报告的计算材料来自用户导入。但“没有直接引用”不等于删除连接器后仍可运行。

本次在独立解释器中禁止导入 `connectors.tushare`、`connectors.cn_a`、`fetch`、`full_market`，实际发现审计导入链原为：

```
strategy_audit → strategy_imports → securities → strategy
  → daily_data → csvimport → connectors.cn_a → connectors.tushare
```

根因是 CSV 的 ST 区间转换借用了联网连接器中的纯数据处理函数。本次把该转换提取到不依赖数据提供者的 `status_intervals.py`，CSV 导入和本地数据源补充直接调用它；联网连接器保留兼容包装。保留原区间算法、来源标识及原有时间约定，没有把约定时间升级为真实历史接收时间。

完整网页的另一路仍为：

```
ui → experience_ui → workflow_ui → paper_auto → daily_operation → full_market
```

因此当前可以验证审计引擎与 CLI 独立运行，但不能从完整包直接删除这些文件。纯审计版需要单独注册网页路由和生命周期，不能只隐藏 token 输入框。

## 功能保留与补材料方式

| 能力 | 移除 Tushare 对现有审计的影响 | 保留方式及边界 |
| --- | --- | --- |
| 代码静态检查、参数核对、费用与账务复算 | 不减少已实现的计算 | 同一次回测的代码、成交、持仓、账户及日志；不执行上传代码 |
| 逐股贡献、回撤贡献、版本比较 | 不减少已实现的计算 | 使用导出账户与成交；缺账务材料时保留受限状态 |
| 相对基准的 β/超额描述 | 无须购买或下载基准行情 | 使用原平台导出的基准净值；缺日期不跨日拼接 |
| 候选池收益/信号诊断 | 仍依赖候选池材料，当前也没有自动调用 Tushare 补齐 | 原平台导出每日打分和候选收盘价，覆盖未买入标的；按模型需要覆盖后续观察日期，不能只用成交标的或打分当天价格冒充完整收益路径 |
| 成交时点、事后价格情景与参与率 | 仍需实际分钟材料 | 原平台补件脚本或用户有权使用的标准 CSV。分钟价须与成交口径一致；参与率要求完整成交前后各两分钟及股/份单位的成交量 |
| 涨跌停封板成交与上市范围 | 解析器已有能力，补件入口原先不完整 | 本次增加涨跌停价、上市退市日期的模板和版本化补传入口；封板检查另需全天区间。上市日期不能证明历史候选池完整 |
| 券商对账、实现短缺、因子归因和风险诊断 | Tushare 不能替代所需独立材料 | 保留独立证据入口；真实母单、完整回报、资金持仓及版本化风险材料仍由用户提供 |
| 从原始行情训练 LightGBM/GRU、在线下载和自动更新 | 属于训练工作台的范围变化 | 从审计订阅版移出；完整工作台继续保留，日后连接器由用户自配并显式启用 |
| 纸面账户自动行情更新 | 需要明确划出产品边界 | 审计的账户规划可读用户材料；已有纸面运行入口及自动更新属于完整工作台，纯审计版不注册相关任务 |

原平台补件也受用户的数据权限、导出能力和价格口径约束。没有分钟权限时，换成补件脚本不会凭空产生分钟证据。日线不能替代分钟，固定涨跌幅不能替代真实特殊日期的涨跌停价，持仓价也不能填充未持有候选的行情。

## 本次已经补的两处材料缺口

1. `audit_materials.py` 原来可以识别 `limits`、`listings`，但没有把它们登记为可单独补传的材料，也没有模板。聚宽/米筐/通用解析器已有读取能力，BigQuant 专用解析器则漏接这两种标准表。本次补齐字段、说明、入口及 BigQuant 读取，仍创建待确认的新版本，保留原输入与报告。
2. `temperq_supplement.py` 原来主要导出成交后十分钟，参与率检查却要求成交前后各两分钟。本次增加成交前两分钟的请求标签，只输出平台实际返回的数据；缺失、午休和开收盘边界仍不能补零。参与率只是事后占用描述，不认证冲击或真实容量。

脚本目前针对聚宽/米筐研究环境；本次没有新增或实测 BigQuant 在线补件适配。BigQuant 和其他来源可通过标准补件 CSV 接入。脚本导出的候选收盘价范围也仍受输入打分日期限制，完整后续观察区间是下一步需要完善的能力。

## 建议的订阅版拆分顺序

1. 建立独立的审计网页入口，只注册策略导入、审计、归因、比较、账户规划和独立证据页面；不注册训练、行情下载、后台 worker、纸面自动运行及其 HTTP 操作。启动时不加载纸面账户调度器。确认有可复用代码再抽取共享页面样式，避免复制审计算法。
2. 发布时明确区分“纯审计版”和“完整工作台”。纯审计版不携带本机配置、行情缓存、token、第三方网关默认值；菜单隐藏必须配合服务端路由不存在的检查。已授权使用的数据由用户导入，不由产品统一供应。
3. 把证券代码规范化和报表格式工具从训练/账户模块进一步提取，收窄传递依赖后再减少 LightGBM、BaoStock 等安装项。`recipe.py` 留在训练线，审计输入继续使用独立的 `strategy_export_v1`，无需改成另一种 Tushare recipe。
4. 围绕当前策略生成补件清单：精确列出证券、日期、所需观察窗口、缺失项及它能解锁的检查。原平台按清单导出，避免用户下载全市场；缺项继续显示“未审”，不自动降低证据门槛。
5. 完善平台补件适配及原始来源说明：统一证券标识、时间区间、股/份/手单位、价格复权口径和真实发布时间；优先打通常见平台的批量导出，再支持用户自有本地文件。不要内置一个仍需联网的新供应商来代替被移除的依赖。
6. 新发行包在连接器文件不可导入、无 token、断网条件下走实际 HTTP 导入→补件→确认→审计→报告下载及升级回归。对所有被移出的在线 POST 路由验证不可调用；检查旧工作台路径仍可使用。

这能缩小产品统一提供行情的范围；仍需按各平台许可处理用户导出材料，不能仅凭技术拆分宣称所有数据授权问题已经消失。
